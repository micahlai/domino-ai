# Canvas presentation packet v1

Presentation-only boundary for R1 other-computer UI. Backend owner adapts durable records into this view. This packet is not a persistence schema. Put TypeScript presentation types in components/investigate/types.ts. Prefer these concrete fields over a general node/plugin registry.

- Workspace props (optional to preserve initial route): sessionId?:string; nodes:CanvasNode[]; edges:{id:string,source:string,target:string}[]; messages:{id:string,role:"user"|"assistant"|"system",text:string}[]; connection:"live"|"loading"|"offline"|"unavailable"|"preview"; pending?:boolean; error?:string; onSend?:(text:string)=>void; onReveal?:()=>void; onAlternative?:()=>void; canReveal?:boolean; canAlternative?:boolean; renderOutput?:(node:CanvasNode)=>ReactNode.
- CanvasNode: id:string; kind:"domino"|"agent"|"source"|"tool"|"output"; title:string; status:"idle"|"queued"|"running"|"succeeded"|"failed"; summary?:string; outputText?:string; error?:string; evidence?:{id:string,title:string,url?:string,publishedAt?:string,excerpt?:string}[]; profile?:{role:string,workingStyle:string,instructions:string,version:string,tools:string[],provider?:string,model?:string,knowledgeCutoff?:string}; metadata?:{label:string,value:string}[]. Use status/evidence as supplied, do not invent them.
- Default absent props retain exactly one idle Domino and disabled submission. Real caller supplies loaded history as initial snapshot: never animate initial restoration. Subsequent new IDs/status transitions may animate once using existing Motion, respecting reduced motion. Reset graph/message/selection state by sessionId, preserve dragged positions and selected node when callbacks/queries update. No timers or random progress. Do not parse text to invent operations.
- onSend records one question via parent; presentation never calls providers. Persistent conversation is parent-backed records; local draft can use session-scoped storage. No optimistic success/agent messages. Pending/error/unavailable state must remain distinct from empty.
- Node details contain evidence/status/output and profile. Visible label says Instructions and working style, not human personality. renderOutput displays existing financial chart/detail via later G3 wiring; no money math in these components. Safe text rendering, safe http(s) evidence links. Technical IDs/methods only in a collapsed details section.
- Preview fixtures may exercise graph updates only under explicitly labelled /playground/agent-canvas. Use manual controls; do not stage fake agent runs on /investigate. Do not connect this route to new backend APIs in R1.
