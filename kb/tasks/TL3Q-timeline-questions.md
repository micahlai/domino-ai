# TL3Q: evidence questions and natural-language event/rule proposals

- **Goal:** pinned one-shot questions answer from saved evidence or yield confirmed event/rule proposals, clarification or saved failure.
- **Folder:** apps/web/convex/timeline (ONLY questions.ts, questions*.ts or questions/**; no workspace/baselines/refs/schema edits).
- **Contracts used:** ChangeSchema, ConstraintSchema, OperationSummaryV1, WeeklySeedV1, Forecast; strict Zod boundary parsing.
- **Done when:** convex-test plus adapter tests cover evidence answer, late invoice equality, expense+cash rule, vague/missing/unsupported clarification, malformed/refused/truncated/provider failures, context isolation, saved request deduplication/conflicts, lease expiry, reload without provider, validated exact proposal link. pnpm check and separate Convex typecheck pass after backend integration.
- **Notes:** frozen interface kb/features/timeline/TL2-TL5-interface.md; workspace get via typed function ref/strict projection, schema supplied by TL2B. Read Convex guidelines; this is bounded one-shot intent extraction with operation receipts, no custom LLM conversation agent. May use a strict documented grammar for common cases and optional one-shot Anthropic fetch only to interpret intent; never calculate money or trust generated answers. Answers derived from actual saved schedule/records, dates and outputs. No private agents imports/shared contracts. No runtime/env/live provider calls (lead verifies). User authorizes parallel through TL5. Commit TL3 steps, Result only, no merge/push.

## Result
- Done: `ask` action / `list` query / `link` mutation per the frozen interface, plus internal `claim`/`finalize`/`expire`. Each ask reads one saved run through `timeline/workspace:get` (typed ref, strict WorkspaceRun projection plus company/run/baseline identity checks), tries the fixed grammar, binds the request (claim, scheduled lease expiry) before any provider call, and saves one strict receipt. Answers, citations and proposals come only from that run's saved forecast, receipts, dominoes, history and seed records; money is only formatted, never computed. Proposals are validated `Change[]` and full-replacement `Constraint[]` (or null); `link` requires a direct child of the asked run with exactly those changes and rules, and binds once. Without `ANTHROPIC_API_KEY`, unreadable wording is saved as failed `PROVIDER_UNAVAILABLE` with no call. `pnpm check` passes (web 588 tests, lint clean) and `tsc -p apps/web/convex/tsconfig.json` passes. Tests: 38 convex-test cases (evidence answers, late invoice equality, expense + min-cash rule, 10 clarification cases, provider unavailable/refused/truncated/HTTP/malformed/invented-words, context isolation, strict projection drift, request dedupe/conflict, lease expiry and late finalize, reload without provider, exact link/mismatch/conflict) plus 17 adapter and 15 parser tests.
- What changed (files): `apps/web/convex/timeline/questions.ts`; `questions/{table,context,intent,grammar,parse,resolve,provider,receipt}.ts`; tests `questions.test.ts`, `questions/provider.test.ts`, `questions/parse.test.ts`; fixture `questions.fake-workspace.test-support.ts` (two dots, so Convex never deploys it).
- Watch out:
  - Schema: `questions/table.ts` defines `timelineQuestions` with the frozen columns/indexes, and the functions are typed against that one-table model (generic builders) so they compile before TL2B's schema lands. At integration, add the table to `schemas/timeline.schema.ts` (it can reuse `timelineQuestionsTable`) and update the schema composition expectation. The test schema adds the table only if the real schema does not already define it.
  - Workspace: tests run against a fake `timeline/workspace:get` built with the real engine from the Kestrel seed. The projection is `.strict()` to the interface's WorkspaceRun/SavedBaseline fields, so any extra or missing field in TL2B's real `get` fails closed (`INTEGRITY`). Run one real-backend ask after merge.
  - Ids: `questionId` is `timeline:question/<requestId>` (company-scoped; `link` reads it back). New rule ids are `q_<requestId>_<n>`. Rule evidence is `{source:"document", ref: questionId}`.
  - Provider (not exercised live): one raw `fetch` to the Messages API (`anthropic-version: 2026-10-21`), model `TIMELINE_QUESTIONS_MODEL` or `claude-opus-5-5`, effort low, structured output `json_schema` (no forced tool_choice, which Opus 5.5 rejects). Every copied word must appear in the prompt. Refusal, max_tokens, non-end_turn, HTTP, timeout (30s), or any non-exact reply becomes a saved failure code; raw text is never stored. Server-side refusal fallbacks are not enabled: a refusal stays a saved failure. The lead should verify one live call.
  - Lease: 90s. A scheduled `expire` (or a retry with the same request) marks abandoned running asks `LEASE_EXPIRED`; a late `finalize` cannot overwrite a terminal receipt.
  - Grammar limits: clauses split on "and" / ";" / "." / a comma not before a digit, so a counterparty like "Smith and Co" splits. A counterparty must be capitalized words after "to"/"from". Item questions need words like when/due/status/about. Anything else goes to the provider, or becomes a saved failure.
