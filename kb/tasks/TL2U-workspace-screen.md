# TL2U: interactive saved Timeline workspace

- **Goal:** user selects saved data, edits rules, adds explicit or prompt-proposed events, compares and reopens saved scenarios through TL4.
- **Folder:** apps/web (ONLY components/timeline/workspace/**, components/timeline/baseline/BaselineLive.tsx, app/c/[companyId]/timeline/** and components/timeline/seam/TimelineSeamHarness.tsx if needed; no backend files).
- **Contracts used:** Change, Constraint, Forecast, HistoryWeek, WeeklySeedV1, OperationSummaryV1, baseline SavedBaseline; validate wire with Zod.
- **Done when:** playground entry + working route, SVG history/13-week chart/selectable items, rule editor, event form, evidence/violation panels, question proposal/confirmation/clarification/failure, paginated catalog/ancestry/reopen. Tests verify boundary states, confirmation reset and stable retry. Typecheck/check pass; screenshot review is lead's integration gate.
- **Notes:** read skills/ui-build and design spec. Follow frozen local interface kb/features/timeline/TL2-TL5-interface.md. Backend/questions workers run concurrently; use typed name refs and local projection schemas, no backend runtime imports. Reuse baseline formatting and shared UI primitives. All financial values/deltas server-produced; no engine/math in UI. Skip components/timeline/dashboard/Dashboard.tsx. No shared styles/schema/contracts, no runtime/env/provider calls. User authorizes parallel implementation. Commit TL2/TL3/TL4 screen steps; no merge/push. Don't wait for backend: wire exact interface with test fixtures.

- What changed (files): `apps/web/components/timeline/workspace/` with these files: `api.ts` (refs by name for workspace and questions functions; exact Zod projections built on `exactBoundarySchema` and shared schemas; identity checks for company, run, baseline, parent/kind and comparison length; a 100-entry graph bound; `parseWeeklyResultRefJson`; links; ancestry walk that detects cycles and missing parents), `requests.ts` (RequestLedger: same id for an uncertain retry, `renew` only after a definite failed receipt; payload-bound `isConfirmed`), `drafts.ts` (string/BigInt dollar parsing, three rule kinds, five event kinds, history dates rejected, open invoice/unpaid bill options taken from the seed), `WorkspaceChart.tsx` (26-week history, saved forecast, dashed parent line, min-cash limit lines, scheduled-item count markers that add no money, click and keyboard range selection), `RunPanels.tsx` (chosen week and items, server comparison deltas, rule receipts with relation and evidence, projected impact, changes), `RuleEditor.tsx`, `EventForm.tsx`, `QuestionsPanel.tsx` (answered/proposal/clarification/failed/running; proposal confirm, then simulate, then link, with a "tie it again" recovery when the link fails), `CatalogPanel.tsx`, `WorkspaceView.tsx` (props only), `WorkspaceLive.tsx` (Convex wiring), `WorkspacePlayground.tsx`, `fixtures.ts`, `workspace.test.tsx`. Also `app/c/[companyId]/timeline/page.tsx`, a link in `baseline/BaselineLive.tsx`, and a section in `seam/TimelineSeamHarness.tsx`.
- Watch out: (1) Assumed failure `errorCode` values (`no_provider`, `timeout`, `refused`, `invalid_output`, `abandoned`) get plain text. Any other code shows generically, so align the names with the questions worker. (2) The catalog page wrapper is passthrough, so Convex `splitCursor`/`pageStatus` are allowed, but each entry is parsed exactly. (3) `simulate` from the event form sends no `constraintsJson`; combined rules and changes are sent only for question proposals. (4) Event dates are only checked against the first forecast week; the server owns the horizon end and its explanation. (5) User-entered rules use evidence `{source:"document", ref:"timeline:workspace/person-entered-rule"}` and ids `rule_<kind>_<n>`, while edits keep the saved id, evidence and consequence. (6) After a successful rules/events write the UI moves to the new run; a proposal run stays put and shows "Open it". (7) Not run against a real backend yet: the function names follow the frozen interface (`timeline/workspace:*`, `timeline/questions:*`).
