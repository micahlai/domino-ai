## Result
- Done: separate additive entry point `runHistoricalSpecialist(env, input, options)` in `@domino/agents` for roles evidence_analyst and scenario_reviewer. The five AgentJob jobs, router, CREAO and their public APIs are unchanged. Chosen smallest approach: pull the Claude Messages POST and reply checks out of `createClaudeClient` into `requestClaudeJson` (same boundedFetch, manual redirects, stop-reason and single-text-block rules), reuse `ProviderError`/`failer` and `encodeData`. No Branch/Snapshot is built from quarterly data. Counterargument: adding a sixth AgentJob would reuse the router, but it would widen the Agents interface, router, CREAO prompts and schemas for one Claude-only call.
- Contract (`@domino/contracts`, new `historical-specialist.ts`): `HistoricalSpecialistInputSchema` is strict and bounded (question 1000 chars, history 8 turns x 2000, sources 20 with excerpt 4000, facts 80, assumptions 20, runs 2, comparisons 40). It freezes visibility at `visibleThrough`: no source, fact or run cutoff after it. Every reference must resolve inside the packet: fact sources, derivations, assumption basis and dependencies, comparison runs and observations, run caseId. Role rules: the evidence analyst gets baseline runs only. The scenario reviewer needs an alternative run plus its baseline. `HistoricalSpecialistOutputSchema` is strict `{assessment <=1200, citations 1..12 {kind,id}, uncertainties 1..5}`. Unknown keys such as `reasoning` fail, and duplicate citations fail. `checkHistoricalSpecialistOutput` rejects citations outside the role's supplied refs (engine = run or comparison id). It requires a source or fact citation for the analyst and an engine citation for the reviewer. It rejects digit money amounts or figures, and bankruptcy-prevention or guarantee phrases. Issue messages are fixed strings and never echo input or output text.
- Provider behavior: input is validated before config, then one POST with `max_tokens` 1500 (default), 60 s timeout, 256 KB request and response caps, no retries or fallback. The JSON schema enumerates the allowed citation ids. Source text, history and the question are labelled untrusted in the system prompt, and `<`/`>` are escaped. The result reports `provider: "claude"`, the model Claude reports (not the configured one) and token usage. If the reply has no model or usage, it fails `malformed_response`. Failures are sanitized `ProviderError`s with job `historicalSpecialist`: `invalid_input` (new category), `config`, `input_too_large`, `refusal`, `truncated`, `unexpected_stop`, `http_status`, `redirect_rejected`, `timeout`, `network`, `response_too_large`, `malformed_response`, `invalid_output`.
- Files/checks: `packages/contracts/src/historical-specialist.ts` + `.test.ts` (28 tests), `packages/contracts/src/index.ts` (one export). `packages/agents/src/historical.ts` + `.test.ts` (20 tests), `claude.ts` (extraction; optional model/usage parsing), `errors.ts` (`ProviderJob` type widens `ProviderError.job`; `invalid_input` category), `index.ts` (exports). Passed: contracts vitest 225/225 and tsc; agents vitest 255/255 (all offline, fake runtime) and tsc; biome check on the 8 changed files. Not run: full `pnpm check`, build, apps/web typecheck, any live provider call.
- Limits: the money and overclaim guards are regex heuristics. Spelled-out amounts ("forty million") or reworded claims pass, so the server must never parse figures from model text. `ProviderError.job` widened from `AgentJob` to `AgentJob | "historicalSpecialist"`; no repo reader narrows on it (grep), but Codex should confirm apps/web typecheck. The live response's `model`/`usage` fields are assumed present per the Messages API; Codex live smoke should confirm. Call budget: exactly 1 provider request per call, 0 in this phase. Persistence, statuses, idempotency, choosing `visibleThrough` and keeping post-reveal evidence out of initial tasks belong to G2b.

## Repair1 result
- Done by the Opus lead alone (no worker spawned): the contract is small and data-integrity critical, and the provider tests depend on its exact shape.
- Input reshaped (no deployed consumer): `{role, visibleThrough, question, history, case: HistoricalCaseSchema, run, baseline?, comparisons, excerpts[{sourceId, text<=4000}]}`, strict outer object. Removed the projected `caseId/companyName/sources/facts/assumptions/runs` and `HistoricalSpecialistSourceSchema`. The case is the canonical visible case (real url/hash/timezone fields, nothing invented). Unknown keys inside case/run are stripped on parse, so only parsed fields reach the provider.
- Audit 1 (run closure/hindsight): `HistoricalRunContextSchema.safeParse({case, run, baseline})` is forwarded. It rejects unknown or future sources, facts and assumptions, rule sources outside run inputs, and hindsight or selectedAfterReveal in a baseline. Every case source and fact must be at or before `visibleThrough`. A run cutoff after `visibleThrough` fails. Before the reveal (`visibleThrough <= cutoff`), the case may not hold any hindsight or selectedAfterReveal assumption, even an unused one.
- Audit 2 (comparisons): each run's comparisons go through `HistoricalComparisonContextSchema` with `revealedThrough = visibleThrough`. That checks prediction and rule existence, metric/period/currency match, observation after the cutoff and by the reveal, exact predicted/observed values and error math, and rule outcomes. A comparison for a run not supplied fails. Run, baseline and comparison ids share one engine namespace (duplicates fail).
- Audit 3 (baseline): the run context requires the named baseline to be present, baseline-kind, with the same cutoff, origin and nowcast. A self baseline fails as a duplicate engine id. New closure rule: the alternative's sources and facts equal the baseline's, and its assumptions equal the baseline's plus the decision ids, with the decision not already in the baseline. Analyst: one baseline run, no `baseline`. Reviewer: an alternative run.
- Audit 4 (caveats): an overclaim match is excused when a negation (`no|not|never|cannot|without|nor|n't`) appears earlier in the same clause. Clauses split on `. ; ! ?` and but/however/yet. Accepted: "There is no guarantee of a positive outcome.", "This analysis does not show that bankruptcy could have been prevented." Still rejected: "This is not a forecast, but the cut would have prevented bankruptcy.", "We guarantee a positive outcome.", "The company will go bankrupt."
- Audit 5: an unknown citation now gives the fixed `citation not allowed` with no id. Input issue messages are the context schemas' fixed strings.
- Provider (`packages/agents/src/historical.ts`) unchanged: one call, max_tokens 1500, no retry or fallback, sanitized errors. The citation enum now comes from case/run/comparison ids.
- Real 2U tests: new non-exported `packages/contracts/src/historical-2u.test-support.ts` builds packets from `data/historical/2u/case.json` + `protocol.json`. No new fixture file. The case is filtered by availability like the server's visibleCase. The inputHash is a real sha256 of the inputs. Comparisons follow engine compareRun and are asserted equal to the period-2u engine literals (baseline error 3,758,000,000 cents; response 4,184,250,000). All four packets (analyst/reviewer x cutoff/reveal) parse. Every audit probe scenario is reproduced on mutated copies of the real packet and rejected. Agents tests confirm no outbound call for future source, unknown run fact, fabricated comparison, self baseline, missing baseline and hindsight. They also confirm the request body has no S8/H/D ids or raw markup, and that a negated caveat is accepted in one call.
- Files: `packages/contracts/src/historical-specialist.ts`, `historical-specialist.test.ts` (72 tests), `historical-2u.test-support.ts` (new), `packages/agents/src/historical.test.ts` (27 tests), this card.
- Checks passed: contracts vitest 269/269 + tsc; agents vitest 262/262 + tsc (includes the existing offline smoke file); biome check on the 5 changed code files. A temporary probe printed issue messages to confirm each key negative fails for its intended reason; it was deleted. Not run: full `pnpm check`, build, apps/web typecheck, data/ and engine tests (untouched), any live call.
- Limits: the caveat and money guards are still pattern checks and cannot prove prose true. "Not only would this prevent bankruptcy", reworded claims and spelled-out amounts pass, so the server must never parse money from model text. Free text (assumption descriptions, excerpts, history) cannot be checked for leaked future facts; G2b must select it server-side. Unscored comparison reasons are not checked against the case. The decision assumption is not required to carry a oneTimeCost. Agents tests import contracts test support by relative path.
