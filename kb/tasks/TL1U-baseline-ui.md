# TL1U: import and reopen baseline

- **Goal:** User loads the labelled weekly fixture, reviews assumptions, saves and reopens its forecast.
- **Folder:** `apps/web/components/timeline` only (existing TimelineSeamHarness is playground entry).
- **Contracts used:** WeeklySeedV1, CompanyModel, Constraint, Forecast, HistoryWeek, PastEvent; TL1B results.
- **Done when:** /playground/timeline-seam saves a real baseline and opens by stable runId URL parameter; reload preserves result; errors visible; render checks/check/build/browser pass.
- **Notes:** ../features/timeline/TL1-implementation.md; ui-build/taste; no shared UI or route modifications. Depends TL1B.

## Result
- Done: UI side only, built against the fixed `TL1-interface.md` (backend TL1S/B is a separate worker; not integrated or browser-checked here). The harness now opens with a "Baseline forecast" section: you load the labelled Kestrel peer fixture or paste weekly seed JSON (checked in the browser with `verifyWeeklySeedText`), start from an explicit neutral model with no cash rules and a note (Advanced JSON for the model and rules), and must tick a review box before Save turns on. Save calls `timeline/baselines:save` with one request id per exact payload (retrying the same inputs reuses it), checks the answer, then `router.replace`s to `?companyId=&runId=` built with URLSearchParams. With a link present, `timeline/baselines:get` goes through `useQueries` and a strict boundary parse (`SavedBaselineSchema`, exact projection; wrong company or run counts as unusable). The read-only `SavedBaselineView` (props only) shows a headline naming the saved low-point week and amount, 13 weekly rows with exact dollars (start, in, out, end, usable), the saved low week marked, saved dominoes or an honest "none saved" line, the assumptions (note, model counts, rules), where it came from (seed id, seed/input fingerprints, method, run id, saved time, past-week/event counts), and expandable original seed/model/rules JSON. Loading, not found, half link, unusable answer, query failure, save failure and "not connected" all show plain-words states. The old quarterly harness sections are unchanged and stay below. No money math in the UI; `formatExactCents` only formats.
- What changed (files): `apps/web/components/timeline/baseline/{api.ts,format.ts,BaselineImportForm.tsx,SavedBaselineView.tsx,BaselineLive.tsx,baseline.test.tsx}`; `apps/web/components/timeline/seam/TimelineSeamHarness.tsx` (mounts `<BaselineLive />`).
- Checks: `vitest run components/timeline` passes (15 tests), `tsc --noEmit` passes for web, biome is clean on `components/timeline`, and `next build` passes (`/playground/timeline-seam` still static; `useSearchParams` is inside Suspense). Not run: full `pnpm check`, Convex typecheck and the browser save/reload smoke; these wait for the backend.
- Watch out: the function refs use `makeFunctionReference("timeline/baselines:save"|":get")`. After codegen, they can switch to `api.timeline.baselines.*`. If the backend's `get` adds any field (including `_id`), the view shows "cannot be shown" on purpose. `savedAt` must be an ISO datetime. The save error text passes through a string `ConvexError` (or `{message}`) reason; anything else gets a "may or may not have been recorded" message. Request ids live in memory, so a full reload before a confirmed save gets a new id.
