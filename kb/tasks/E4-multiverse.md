- Assumptions and conventions (all named in code and evidence notes):
  - Late payment, chance: paid invoices observable by asOf (paid ≤ asOf) that were more than 14 days late, divided by all observable paid invoices for that customer. With fewer than 3 samples the chance is the documented 0.1, and the evidence says it is an assumption.
  - Late payment, delay: extra days = max(0, round(p90) − round(mean)) from `model.customerDelayDays`. With no model entry, or 0 extra days, no risk is produced.
  - Non-renewal: only deals with `kind: "renewal"`, a string `invoiceId` and a linked unpaid invoice. Stage `lost` is skipped. Chance is 0.25, or 0.5 if won but unsigned, labelled as an assumption. Nothing is inferred for Orbit usage, churn, customer failure or news.
  - Spend spike: card records only, never bank. Compares the latest four complete Monday–Sunday weeks ending on or before asOf with the four weeks before. It fires only if 5·(recent − earlier) > earlier and earlier > 0, as a `remove_cash` of the difference on week zero's Monday. Chance 0.3 is a labelled demo assumption. Evidence cites the card records from both windows.
  - Risk filtering and ranking: candidates whose weekly inflow/outflow is unchanged are dropped. Impact = base low − scenario low. Ranking is exact probability × impact using `decimalRatio`/BigInt, ties broken by ID, top 5 kept.
  - scoreFix: changes are ancestorChanges + parent.changes + fix.changes, in that order. A non-root parent without context throws; `[]` is accepted. The branch ID is `${parent.id}__${fix.id}`. Status is always `proposed`. riskIds is copied from the parent, or left out when the parent has none. Dominoes get context with the parent's recomputed forecast as the baseline. Critical-bill delays still throw from forecast.
  - rankFixes: rejects a branch whose parentId differs, or whose forecast doesn't match its schedule (via `verifiedSchedule`). Keeps gain > 0, then orders by: clears all rules (zero breached in the shared evaluator, runway included), larger gain, lower risk, then fix ID.
  - stressTest risks: impact is recomputed through forecast. The input `impactLowPoint` is ignored for ranking and for deciding which risks are adverse. Risk changes are applied in sorted risk-ID order, then applicable fixes in caller order.
  - stressTest universes: IDs are `u_base` or `u_<sorted ids joined by +>`, so they don't change when fixes toggle. Survival uses the shared min_cash/pay_by_date evaluator. Runway is ignored for survival. Pay_by_date deadlines past the horizon don't count as breaches. `breaksAt` is the Monday of the earliest breach (date first, then constraint ID).
  - stressTest scores: survivalRate = surviving weight / total weight. Weights are base = 1, otherwise the product of the risks' chances, in float, which is not money.
  - Delay breaking point: computed only when the no-fix base survives. Uses the highest-ranked risk that has exactly one `delay_invoice` on an invoice whose base receipt is ≤ the last forecast Sunday. Searches extra days 0..daysBetween(receipt, last Sunday)+1. The reported threshold is total days late: round(mean) + the smallest failing extra. The scenario's own delay is not added on top. If the selected risk can't break the rule, there is no point (no falling back to the next risk).
  - Loss breaking point: uses explicitly linked renewals (not stage lost) with in-horizon unpaid receipts. Searches 0..sum of those receipts in cents. Losses are cut from receipts in expected-date then invoice-ID order, by lowering the receipt items themselves, so both the weekly fold and the funding replay see it as a same-day inflow. No public Change is added.
  - Breaking-point search: binary search on a monotone predicate. Tests compare it with brute force on small cases.
  - history: cashOnHand is taken as the bank balance at the end of asOf. Bank transactions after each close and on or before asOf are undone. The last bucket is the Monday containing asOf, closing at asOf (a partial week). Usable = closing − today's restrictedCash, held constant. `weeks` must be a whole number ≥ 0.
  - pastEvents: late payments (more than 14 days, paid ≤ asOf); signed won deals over $50K with close ≤ asOf; payroll increases between consecutive runs ≤ asOf, labelled "Payroll rose…" with kind `other`, not a hire; and a card spike as of asOf. No churn or usage events.
- Watch out:
  - The 200 ms target is met in this environment only. The 1 s test ceiling is a regression guard, not a promise.
  - survivalRate is a weighted index over overlapping scenarios, not a calibrated probability.
  - Probabilities computed as k/n (for example 1/3) are binary floats. Ranking compares their shortest decimal exactly.
  - Fixture risk IDs (`risk_acme_late`) differ from scanned ones (`risk_late_inv_acme_2027`), so fixture fixes don't target scanned risks. E5/E7 wiring must validate targets.
  - Joined universe IDs could collide if a risk ID contains `+`. Not guarded.
  - Loss sensitivity reports one combined threshold across all renewals. Delay sensitivity tests one invoice only.
  - Pair generation uses the top four ranked risks, including positive ones if fewer than four are adverse.
  - Still open: grade/learn, automatic positive-event discovery, supplying contexts from Convex, and the seeded-data backfill.
