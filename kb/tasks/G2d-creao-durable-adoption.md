# G2d: connect app-scoped CREAO to durable specialist operations

- **Goal:** default CREAO mode dispatches the accepted historical adapter exactly once, persists actual remote identity before polling, validates output and truthfully records uncertainty.
- **Owner/files:** apps/web/convex/investigation.ts, investigation tests, narrow optional operation fields in schema.ts if required, generated bindings if required; kb/coordination/historical/investigation-api.md and this Result only. No UI/package/contracts edits.
- **Dependencies:** G2b7801fb5 + G2cabb6d07. Read both API packets and kb/spec/creao-canvas-cycle.md. Reuse runCreaoHistoricalSpecialist and existing durable operation lifecycle.
- **Rules:** only app-scoped role credentials, no account/developer key or fallback. Missing config fails with no call. Require explicit server-side historical-profile verification gate defaultoff until Codex verifies dedicated remote app instruction/memory compatibility; fail honestly while off. Do not manufacture verification.
- **Profiles:** snapshot exact safe app-authored rules for actual provider/version, distinguish supplied per-run rules from unknown remote system instructions. Freeze mode/profile before dispatch and reject drift before call. Remote id/status persisted by onRunCreated with owner/lease/running guard, no public write endpoint; no polling if persistence fails. Unknown model/usage omitted, never invented.
- **Failures:** lease bounds encompass provider deadline. One create maximum, no retries/resumes after uncertain create, callback or timeout. Record provider/run when observed without declaring success before validation. UI may expose coarse lifecycle only. Preserve all G2b isolation/ownership/frozen input guarantees.
- **Acceptance:** focused tests for missing gate/config zero calls, CREAO success without model/usage, identity persisted beforepoll, late callback/expiredlease cannot overwrite, uncertain create/record/deadline no retry, unchanged explicit claude-dev behavior. Offline mocks only. Codex independently audits/fullchecks/runtime and actual CREAO configuration/call later.
- **Skills/budget:** /orchestrator /ponytail full. One Opus/high process, nochildren,45min boundedcheckpoint. No fullsuite/build/server/livecalls/secrets/cloud/push/merge/sharednotes. Other workers ownUI; preserve their work. No main.

## Result
- Status: offline worker candidate, 2026-10-24. Not live-accepted. Contract details are in `kb/coordination/historical/investigation-api.md` "Provider seam (G2d)".
- Default `creao` now dispatches `runCreaoHistoricalSpecialist` once per claim. Mode and profile freeze at operation creation; a mode change (`provider_changed`) or profile drift (`profile_mismatch`, which also checks the exact prompt being sent) fails with no call.
- Gate: `DOMINO_CREAO_VERIFIED_PROFILES` (comma list of verified CREAO profile versions), default off. While it is off: `failed/provider_unverified`, zero calls. It is bound to the version, so editing the rules requires verifying again. I did not set or manufacture any verification.
- CREAO profile: per-run rules plus output format, `role@creao-<hash12>`, `provider: "creao"`, and an `instructionsScope` note that the remote app's own instructions and memory are unknown. The claude-dev profile and behavior are unchanged.
- Identity: `internal.investigation.recordRemoteRun` (internal only; no public endpoint) writes `provider`, `remoteRunId` and `remoteStatus` only for the live claim (`startedAt`) of a running, unexpired CREAO operation that has no recorded run yet. If it fails, the adapter stops with `run_record_failed` and does not poll. Success also requires `runId === remoteRunId`. `model` and `usage` are left unset for CREAO.
- Lease: the CREAO run deadline is min(150 s, lease - now - 10 s). With under 30 s left, nothing is created. CREAO outcomes that are uncertain (timeout, network, deadline, poll_limit, run_record_failed, http_status, malformed_response, unknown_status) end `unknown` and are never retried.
- Schema: two optional server-only fields on `investigationOperations`: `remoteRunId` and `remoteStatus`. `getConversation` omits both. Generated bindings did not need to change (they are module-typed).
- Tests (offline fakes): `apps/web/convex/tests/investigation.test.ts` has 21 tests, 6 of them new: CREAO profile snapshot; gate off or missing config makes zero calls (with an account key present); success with no model or usage, identity in the DB at the first poll, exact URL and app-key auth, reload makes no new call; an expiry between create and callback means no poll, plus claim, duplicate, expired-lease and wrong-run guards; network failure on create, a deadline inside the lease, and too little budget, each with one create at most; provider switch makes no call. Three existing tests now set dev mode explicitly because the mode freezes at creation. Mutation check: removing the lease bound or the claim guard fails 2 tests.
- Verified: `tsc --noEmit` (apps/web), biome on the 3 code files, vitest investigation + historical (34/34). Not run: full suite, build, server, browser, live CREAO.
- Open for Codex: create and configure the dedicated per-role CREAO apps and their memory isolation, then set the gate to the verified versions. The rebuild of the CREAO rules from the Claude prompt is checked against the actual prompt at dispatch, so if the package wording changes it fails closed (`profile_mismatch`) and does not mislabel. Counterargument: exporting `historicalRules` from `packages/agents` would be cleaner, but that file is outside this card's scope.

### Repair1 Result
- Status: offline worker candidate, 2026-10-24. Not live-accepted.
- The CREAO profile now freezes the role's non-secret `appId` at creation (never the key). Dispatch fails `app_changed` with no call if the role's current app id differs, before the gate, budget or create. The adapter gets the frozen app id pinned.
- Gate entries are now `appId/profileVersion` pairs. A bare version, or app A's pair, does not authorize app B (`provider_unverified`). Default off is unchanged: gate off still reads `provider_unverified` even with no config; gate on with no app id is `config`. All zero calls.
- Tests: `apps/web/convex/tests/investigation.test.ts` 22 tests (1 new): queued on app A and verified, app id changed to B means `app_changed` and zero fetches; queued on B with only A's pair and a bare version listed means `provider_unverified` and zero fetches. The snapshot test asserts no `appId` without config. The existing success test (verified binding, unchanged) is the positive case. Mutation check: dropping the app check fails the new test; going back to version-only matching fails 4.
- Probe `/tmp/g2d-independent.test.ts`: the swap test now fails its "succeeded" expectation (bypass closed). With its `verify` changed to the pair format, the other 4 pass.
- Verified: vitest investigation + historical (35/35), `tsc --noEmit` (apps/web), biome on the 2 code files. Not run: full suite, build, server, live CREAO.
- Docs: investigation-api.md gate format and order updated. Open for Codex: when you set the gate, list `appId/version` pairs for each dedicated app. `getConversation` now also returns `profile.appId`; it is not a credential, but strip it there if you want it server-only.
