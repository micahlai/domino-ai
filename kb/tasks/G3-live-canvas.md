## Result
- **Done (local commit, not pushed):** `/investigate` now mounts `components/investigate/live/InvestigateLive.tsx` inside Suspense. Files: `app/investigate/page.tsx`, `components/investigate/live/{adapt.ts,session.ts,FinancialOutput.tsx,InvestigateLive.tsx}` plus tests. No other file touched.
- **Adapter (`adapt.ts`):** `getConversation` is zod-parsed, then mapped to nodes/edges/messages. Domino node states the fixed workflow. Source/tool/agent nodes come only from saved operations; edges only from `dependsOn` (roots hang off Domino). `queued` and `running` stay distinct; `unknown` shows as failed with "outcome is unknown"; a succeeded step with unreadable saved output shows as failed. Source summary says "archived copy, not live retrieval" only for `origin: curated_archive`. Provider/model show only what was saved, otherwise "unknown" in details. Output nodes (forecast, reveal comparison, alternative) exist only for succeeded steps whose `outputRef` matches the saved baseline. Provider failure keeps forecast outputs.
- **Money:** output nodes render the existing `HistoricalReplay` via `buildView` from saved `getCase/getRun/getReveal`. The forecast node never reads the reveal, so no future facts show before reveal. An alternative saved before any reveal shows a note ("shown with the reveal") instead of a chart, because the existing view only draws it after reveal. No money math added.
- **Persistence:** conversation id in `?c=`. Reload restores quiet history (initial snapshot is not animated; Workspace keyed by conversation). Request ids are stored per intent (localStorage with memory fallback), kept across retry/reload after an uncertain failure, dropped only after a definite server rejection or success. A reload with an unconfirmed new question shows it back so it can be sent again with the same id. Completions are ignored if the page left `/investigate` or changed conversation (`mayApplyCompletion`, `sendRequest`). Query errors, NOT_FOUND, malformed data, offline and no-deployment are distinct states, none drawn as empty.
- **Fixed workflow:** a follow-up message shows "answers one question, start a new investigation" and a "New investigation" link bar appears once a conversation exists. Follow-ups are not silently sent.
- **Verified:** `npx vitest run components/investigate components/historical` (100 tests pass, 30 new in `live/`), `tsc --noEmit` clean, `biome check` clean on touched paths. No full suite, build, browser, server or provider call.
- **Not verified / for Codex gates:** no DOM test env exists, so `Session` hook wiring (useQueries/useMutation, router.replace, connection state) is covered only through the pure `sendRequest`/`mayApplyCompletion`/adapter tests and static render, not run in a browser. Layout of the new bar plus workspace (`h-full` inside `flex-1`), narrow mobile and keyboard flow need the browser gate. `FinancialOutputView` happy-path chart render is not tested here (reuses historical `buildView`, covered by `live.test.tsx`).
- **Known limits:** the panel clears the draft on send, so a failed new question is quoted in the error text rather than restored to the box. Follow-up Send stays enabled and answers with the error instead of being disabled (panel is not mine to change). Right after a reveal/alternative succeeds there can be a brief moment before the query shows busy; a second press then gets a clear BUSY/LIMIT error.
