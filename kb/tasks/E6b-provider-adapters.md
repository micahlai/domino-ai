## Result (worker fills this in when done)
- Done: Native-fetch Claude and CREAO transports behind the unchanged E6a router. `TURBO_FORCE=true pnpm check` passes (typecheck, all tests, biome); agents has 179 offline tests (20 original router tests kept). No live provider calls, env-file reads or dependency changes. Ready for Codex review.
- Public API (`@domino/agents`): `createAgents(env, options?)` returns `Agents`. `createAgentRuntime(env, options?)` returns `{agents, runJob}`, and `runJob` reports the backend that actually answered. Options: injected `fetch/now/sleep`, `onAttempt(diagnostic)`, and per-provider bounds. `createClaudeClient` and `createCreaoClient` are exported. `createAgentRouter(clients, env, {onAttempt}?)` is unchanged apart from the optional third parameter. `AgentJobError.failures` and `AttemptDiagnostic` carry only `{job, backend, attempt, outcome, category?, httpStatus?}`. `ProviderError` messages are `"<provider> <job> failed: <category> (HTTP n)"`. `hashInput(value)`: Web Crypto SHA-256 hex of canonical JSON (sorted keys, array order kept, undefined properties dropped; rejects cycles, non-finite numbers, bigint, functions, symbols, non-plain objects and undefined array items). `hashJobInput(job, input)` adds the job and `AGENT_SCHEMA_VERSION="e6b-1"`. Nothing reads the environment when the module loads.
- Claude: `POST https://api.anthropic.com/v1/messages` with `authorization: Bearer`, `anthropic-version: 2026-10-21` and JSON content type/accept. The body is exactly `{model, max_tokens, system, messages:[user], output_config:{format:{type:"json_schema", schema}}}`, with no tools or tool_choice. The model comes only from `ANTHROPIC_MODEL`; a missing model or `ANTHROPIC_API_KEY` is a `config` failure with no request sent. Only `stop_reason:"end_turn"` with exactly one text block is accepted. `refusal` maps to refusal; `max_tokens` and `model_context_window_exceeded` map to truncated; any other stop maps to unexpected_stop. The text must parse as the strict envelope `{"result":[...]}` (structured jobs) or `{"text":"..."}` (text jobs). There is no fallback to unstructured prompting.
- Schema formats: hand-written per-job JSON schemas in `src/schemas.ts`. Tests check them against the Zod contracts: object keys and required fields for FixCandidate, Evidence, all eight Change variants, Constraint (C1 `billId`/`consequence`) and FieldMapping. `targetRiskIds` is required from agents. Two dialects: "contract" (exact shape; used in CREAO prompts) and "claude" (every object closed, no min/max/pattern/length keywords, `minItems` only 0/1). In the Claude dialect `FieldMapping.fields` is an array of `{canonical, source}` pairs; it is converted back to the record, and duplicate or `__proto__` keys are rejected. Zod stays the only authority.
- Job rules beyond Zod (`src/semantics.ts`):
  - Constraint evidence must use source `document`, a ref starting with a supplied document name, and a quote found in that document (whitespace-normalised). Consequence evidence is checked the same way, and ids must be unique.
  - Fixes must have explicit `targetRiskIds` that are a subset of `branch.riskIds` (`[]` allowed). Each fix needs at least one evidence item, and fix ids must be unique.
  - Invoice, customer and bill references must exist in the snapshot. A `delay_bill` on a critical bill is rejected.
- CREAO: only `https://agent.creao.ai/api/v1`; any other `CREAO_API_BASE_URL` (developer API, /v2, http) is `config`. Create: `POST /apps/{encodeURIComponent(agentId)}/runs`, Bearer auth, body `{inputs:{prompt}}`. The prompt is JSON `{job, schemaVersion, rules, outputFormat, outputSchema, data}`, with `<` and `>` in the data escaped so input text cannot forge delimiters. A 200/201/202 response with an `id` is required. The worker then sleeps and polls `GET .../runs/{encodeURIComponent(runId)}`; the run id must match. `completed` is the only success. `failed` and `cancelled`/`canceled` are failures; pending/queued/running/in_progress/processing/started/starting keep polling. Any other status is `unknown_status`. Agent ids: `CREAO_AGENT_ID_MAPSOURCE` (README name) or alias `CREAO_AGENT_ID_MAP` (spec name), which must agree if both are set; `CREAO_AGENT_ID_CONSTRAINTS`; `CREAO_AGENT_ID_BRIEF`. `proposeFixes` and `explain` have no CREAO agent (`config`, so the router falls back to Claude).
- Extraction formats: `result.text` (the memory summary) is never read.
  - Candidates come from `result.chatText`: blocks between own-line `<<<DOMINO_RESULT>>>` and `<<<END_DOMINO_RESULT>>>` (optionally fenced), JSON/untyped code fences, or the whole chat text when it is standalone JSON. They also come from JSON artifacts (type containing "json" or title ending in .json); other artifacts are ignored.
  - Structured jobs accept `{"result":[...]}` or a bare array. Text jobs accept only `{"text":...}` or plain text inside the delimiters.
  - Braces in narration and same-line delimiters are never parsed. Every candidate is validated against Zod and the job rules. Identical answers count once; two or more distinct valid answers give `ambiguous_result`; none gives `no_result`.
- Artifact/redirect safety: credentials go only to an artifact URL that, resolved against the base, has the trusted origin, starts with `/api/v1/`, ends with `/runs/{runId}/artifacts/download`, has `artifactId` equal to the artifact id, and contains no userinfo. Redirects are followed by hand (`redirect:"manual"` on every request) for up to 3 hops. Each hop must be HTTPS to a public host. Literal loopback, private, CGNAT, link-local, multicast and IPv4-mapped addresses, IPv6 unique-local and link-local addresses, localhost, single-label hosts and .local/.internal/.home.arpa names are all rejected. Authorization is dropped for good once the chain leaves the trusted origin. Create and poll calls reject any redirect. No URL is stored or reported.
- Bounds (defaults, all overridable):
  - Claude: 120s per-request abort, 512 KiB request, 1 MiB response. max_tokens: mapSource 4096, readConstraints 4096, proposeFixes 8192, explain 512, weeklyBrief 1024.
  - CREAO: 20s per request, capped by the 150s whole-run deadline. 3s poll interval, at most 45 polls. 256 KiB request body, 1 MiB per response, at most 4 JSON artifacts of 1 MiB each, 3 redirects.
  - Size caps apply to the declared content-length and to the streamed byte count. Timeouts abort the fetch.
  - No retries inside the transports; the router still caps a job at 2 primary + 2 Claude attempts. Worst case is about 540s per job.
- Verified cases (offline, injected fetch/clock/sleep):
  - Requests: exact URLs, method, headers, body and auth for both providers; percent-encoded agent and run ids; configuration failures send nothing.
  - Run lifecycle: every terminal and unknown status, malformed create/poll bodies, poll-id mismatch, HTTP status categories, poll limit, deadline, and per-request timeout clipped by the remaining deadline.
  - Size and response handling: declared and streamed size caps, Claude refusal/truncation/other stop reasons, multi-block and non-JSON responses, extra envelope keys.
  - Extraction: narrated and delimited text, fences, standalone JSON, echoed input ignored, duplicates versus ambiguous answers, memory summary ignored, forged delimiters in input.
  - Artifacts: same-origin download, auth stripped across origins and kept off when the chain returns to the trusted origin, 12 rejected redirect targets, hop bound, 6 untrusted initial artifact URLs never fetched, artifact count and size caps.
  - Validation: invalid C1 targets/evidence/bill/consequence fields, all eight change kinds.
  - Routing through the real transports: CREAO success, fallback after two CREAO failures, the 2+2 bound, missing CREAO credentials falling back, no CREAO for Claude-primary jobs, overrides, and a throwing diagnostics hook. Diagnostics and errors contain no keys, URLs or ids.
- Smoke command (for Codex; not run against live providers by the worker): `SMOKE_CONFIRM=live-provider-call SMOKE_JOB=<mapSource|readConstraints|proposeFixes|explain|weeklyBrief> SMOKE_BACKEND=<creao|claude> pnpm --filter @domino/agents smoke`, with keys exported in the caller's environment (vitest does not load .env files into process.env). It calls exactly one provider client directly with synthetic input; there is no router and no fallback. It prints one `domino-agents-smoke {...}` line containing ok, job, backend, reason, category, httpStatus, durationMs and an item/character summary. Validated output is included only with `SMOKE_PRINT_OUTPUT=1`. Without confirmation it exits with failure and `{"ok":false,"reason":"usage"}`; this was verified with no network.
