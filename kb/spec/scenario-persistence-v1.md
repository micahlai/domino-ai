# S4 additive persistence design v1

Status: design independently reviewed, all six reported design issues resolved and rechecked. This is not implementation acceptance. Implementation remains blocked on accepted S2/S3, L0 shared shapes and serialized L5 backend ownership. Existing 2U APIs and rows remain readable; main stays untouched.

## Existing boundary checked

historicalRuns currently has kind baseline/alternative, run/snapshot/summary and rowHash; historical.ts loadRun parses HistoricalRun and validates its frozen inputs. Baseline snapshots intentionally omit A1. investigation.ts already has payload-bound request receipts, sequenced operations, a transactional deterministic tool runner and durable provider IDs. Reuse these tables/functions. Do not change HistoricalRun.branch or pretend a new event is a legacy alternative. No new simulation table.

## Exact additive shapes, L0 defines Zod first

1. Extend historicalRuns.kind with `scenario`. Add optional `parentRunId` and `schemaVersion`; new scenario rows require parentRunId and schemaVersion=1 at application validation. baselineRunId is required for scenario rows; owner remains the conversation. Legacy rows need no backfill.
2. For kind=scenario, row.run is a new StoredHistoricalScenario envelope, NOT HistoricalRun: {schemaVersion:1,id,caseId,createdAt,baselineRunId,parentRunId,baselineRowHash,baselineInputHash,scenarioInputHash,scenarioInput,result,taint}. `result` parses HistoricalScenarioResultSchema. Event parent is the baseline; response parent is an event-only scenario. One event/one A1 response, no deeper ancestry in v1.
3. Scenario row.snapshot is {baselineSnapshot,baselineSnapshotHash,responseExtension?,protocolSnapshot,knowledgeVersionIds}. baselineSnapshot is copied byte-for-byte from the verified baseline. protocolSnapshot freezes protocol ID/hash, response.postHoc/reason and the exact user-visible method/cost/unknown-downside caveats. knowledgeVersionIds pins L5 mapping/resolution/rule versions; empty is allowed only for legacy curated 2U baselines, explicitly tagged legacy.
4. responseExtension is {sources,facts,assumptions,selectedAssumptionId,contentHash}. Select A1 and transitive dependency closure from a version-pinned source package, only cutoff-eligible source/fact basis, retaining original assumption selection/feasibility/date fields. No later held-out facts, no reveal view, no automatic current-CASE read on reload. Build an ephemeral merged case for computation; reject ID collisions with different content. Baseline input manifest/hash stays unchanged. Missing extension evidence blocks the new response; do not rewrite baseline or silently widen it.
5. taint is {eventSelectedAfterReveal,responseSelectedAfterReveal,protocolResponsePostHoc,assumptionPostHoc,reason}. Effective event postHoc is the server event flag; response postHoc ORs all applicable flags, result.postHoc is event OR response. Protocol taint cannot be cleared by a pre-reveal click. Copy validated engine result and elevate its taint fields before final parse; money/predictions are untouched. A1 protocol already has postHoc=true.
6. Extend investigationRequests.kind with `scenario_event` / `scenario_response`; extend investigationOperations.kind with the same. Reuse status, input, outputRef and dependsOn. Add optional typed version-1 scenario context in op.input through the new Zod parser. No schema-level `v.any` data reaches the engine without parsing.

## Public API proposals, not existing exports

- investigation.requestScenarioEvent({requestId,conversationId,event}): event is exactly HistoricalScenarioEventSchema. Server derives baseline, cutoff, target, currency, owner and hindsight state. Require a succeeded, integrity-checked baseline in that conversation. Payload receipt binds normalized event and conversation. Queue one deterministic event op depending on forecast. Return existing {conversationId,operationIds}; no client predictions/hashes/cutoff/lineage accepted.
- investigation.requestScenarioResponse({requestId,conversationId,eventScenarioId,responseAssumptionId}): v1 permits server-advertised A1 only. Load owned event-only parent, require same conversation/baseline/cutoff and unchanged event input. Receipt binds parent ID and response ID. Queue one response op depending on event op. No provider creation here.
- historical.getScenario({caseId,scenarioId}): read-only, validate envelope, baseline/parent, hashes, frozen extension, taint and result; return saved summary/evidence. Never recompute on query. A scenario ID passed to legacy getRun returns a typed wrong-kind error; old getRun callers remain unchanged.
- Add getConversationV2 for all operation kinds and scenario output refs/capabilities. Existing getConversation retains its five-kind projection, legacy output refs/capabilities and legacy operation-state semantics so old adapt.ts/InvestigateLive.tsx readers never receive unknown kinds. It projects only the supported legacy operations, not invented scenario status. V2 and the new UI show the complete history. Reuse shared reads rather than fork persistence. S2 catalog keeps bounded pagination and shows scenario lineage only from existing operation outputs, without scanning the database or changing legacy status precedence. Name exact S2 helper after its accepted interface is known; stop if additional schema index is needed.
- Legacy busy/capability flags must still agree with server gates while a V2 operation runs. An unsupported scenario is not projected as a legacy operation, but it cannot make the old reader advertise a write that the server rejects as busy. Test old/V2 readers concurrently.

## Hash and transaction rules

Use existing canonicalJson/hashInput. scenarioInputHash hashes version, baseline IDs and both pinned hashes, parent ID/hash, parsed input, extension, protocolSnapshot, knowledgeVersionIds and taint. New scenario rowHash covers ALL row lineage fields plus run/snapshot/summary, excluding Convex metadata and rowHash itself. Dispatch legacy rowHash verification by kind so existing hashes stay valid. No hash-as-authorization claim; owner/relationship validation is separate.

request receipts bind kind + canonical semantic payload; same key/same payload returns first operation IDs, same key/different payload conflicts. Deterministic scenario ID uses receipt identity/payload hash. Internal inv: operation keys retain current public/internal separation. Deterministic compute, insert, outputRef, operation success and one receipt/message commit in one transaction. Concurrent same requests converge through receipt/index reads and transaction retry; test this against actual local runtime. Computation failure writes a failed operation through the existing failure handler, never a successful row with missing outputs.

At enqueue, freeze the server's disclosure taint. Conservatively treat an already queued/running/succeeded reveal request in that conversation as post-hoc; fail closed if disclosure state cannot be resolved. Recheck before computation and OR any new taint, never clear it. Responses inherit parent event taint. Original event result remains immutable.

Legacy baselines contain no protocol/package version. Creation of the FIRST event therefore requires an explicit immutable compatibility entry, not an inferred `current` version: archived accepted 2U protocol and response package bytes from the reviewed Git tree, their content hashes, and a verifier matching the legacy baseline's case/method/roles/input snapshot/predictions exactly against that archived bundle. Multiple or zero matches fail new event/response creation with LEGACY_PROTOCOL_UNPINNED; old baseline/alternative/reveal reads still work. Freeze the matched entry/version/hash with the event; the response inherits it and selects its closure from that pinned archive. New L5 baselines carry their actual protocol/source-package pins. No backfill or rewriting old baseline hashes is needed.

Shared-runtime activation is a joint S4/U2 gate: keep new scenario writes disabled until backend/V2 and the frontend adapters/renderers have passed combined checks/browser acceptance. S4 workers test on an isolated candidate runtime only. Old API projection tests must pass even after V2 creates scenarios. Do not deploy S4 alone to preserved3214 or claim a backend-only acceptance completes the product.

Event computes quarterScenario from loadRun's frozen bridge roles/case. Response uses the same baseline plus validated extension and event input; assert its baseline/event predictions and event impact match the saved parent before saving new response. No scenario is scored as observed history. Reveal continues to attach only to baseline; baseline comparisons never change from scenarios.

## Acceptance before U2

- Actual saved 2U baseline with AS-RESTRICTED succeeds; baseline bytes/inputHash/rowHash and existing alternative/reveal remain unchanged.
- Event-only and then A1 response round-trip through real operations/getScenario/catalog; target/amount applied once; response cost/range/lag equals accepted engine output. A1 is post-hoc even before user reveal.
- Same/conflicting request IDs sequentially and concurrently; replay does not append duplicate operations/rows/messages. Foreign owner/parent, mismatched case/cutoff and response-of-response fail.
- Corrupt each lineage pin, input/result amount, extension/source date/hash, protocol taint and summary; reads fail closed. Edited current CASE/protocol cannot change old reads. New work uses only explicitly selected versioned evidence.
- Missing extension, late amendment, future source, unresolved used knowledge role, failed/unknown dependency and queued reveal tested. No automatic retry of uncertain provider creates introduced.
- Legacy getRun/getReveal/direct routes and getConversation five-kind readers work after V2 scenario creation. New query reload makes zero compute/provider calls. Joint S4/U2 activation, full check/build and actual browser acceptance remain Codex gates.
