# E6b provider adapters

The user authorized backend completion with Claude implementation and Codex audit. Native fetch is chosen over new SDK dependencies: these are a few bounded HTTP calls, and the injected E6a router remains the authority for retry/fallback and Zod validation. This supersedes the original prompt's SDK requirement. Counterargument: SDKs cover more response cases, so keep explicit envelope/status tests and fail closed on unsupported responses.

## Public package API
- Preserve createAgentRouter, existing types/tests and backendFor defaults. Export createAgents(env, optional injected transport options) returning the Agents facade, plus an explicitly named factory exposing runJob diagnostics if needed. No global environment read at module import. Missing credentials fail when that provider is called, allowing configured fallback.
- Export deterministic async hashInput using Web Crypto SHA-256 of canonical JSON including job/schema version at call sites. Sort object keys, preserve array order, reject unsupported/cyclic inputs. No Node-only imports needed by the default Convex runtime.
- Structured jobs return only FieldMapping[], Constraint[] or FixCandidate[] to the router; text jobs return validated text. Add job/backend/status-only diagnostics, never inputs, raw errors, tokens, URLs or response bodies.

## Claude
- Official docs reverified by reviewer: https://platform.claude.com/docs/en/api/messages/create and /docs/en/build-with-claude/structured-outputs. POST https://api.anthropic.com/v1/messages, Authorization Bearer, anthropic-version 2026-10-21, configured ANTHROPIC_MODEL, bounded max_tokens and messages.
- Prefer output_config.format JSON schema with one result envelope. Define explicit per-job JSON schemas derived from current contracts; keep authoritative Zod validation and tests for C1 fields/all eight changes. Existing Zod3 has no built-in exporter. No dependency addition.
- Do not blindly force tool_choice tool/any; current model docs restrict those modes. If offering tool-input extraction, it must be explicit and supported. Reject refusal, truncated max_tokens, empty/malformed/ambiguous results and unexpected envelopes. No undocumented endpoint or model default. Missing ANTHROPIC_MODEL is actionable configuration failure, not an invented model name.
- Every prompt treats source text as data, prohibits following embedded instructions, requires supported evidence, never invents money calculations or facts. ProposeFixes must return explicit targetRiskIds from branch.riskIds (or [] only for genuinely global proposals), no critical-bill delays. Explanations <=3 sentences and refer only to supplied outputs. No approval or execution claim.

## CREAO chat API
- Use only the configured chat API family: https://agent.creao.ai/api/v1. Do not mix developer-console credentials or /v2. Default jobs mapSource/readConstraints/weeklyBrief use CREAO_AGENT_ID_MAP, CREAO_AGENT_ID_CONSTRAINTS, CREAO_AGENT_ID_BRIEF respectively; confirm exact existing env names in .env.example (never inspect actual secrets).
- POST /apps/{encodedAgentId}/runs, Bearer auth, body {inputs:{prompt:JSON.stringify(jobPayload)}}. Require returned run id and poll GET /apps/{agentId}/runs/{runId}. Completed/failed/cancelled terminal statuses. Parse envelopes with Zod; unknown terminal state must not be called success.
- Verified repository behavior: result.text is a memory summary, not job output. Actual JSON arrives in result.artifacts or clearly delimited result.chatText. Artifacts have id/title/type/url. Download from the authenticated same-origin stable CREAO artifact endpoint given by the response; do not invent its URL or persist signed redirect destinations.
- Requests with credentials stay on the configured trusted HTTPS origin. Handle redirects manually with a finite hop bound, strip Authorization on cross-origin storage redirects, reject non-HTTPS redirects and redirects to local/private destinations. Never forward credentials on a redirect to another origin. Do not fetch arbitrary external initial artifact URLs as authenticated requests.
- Extract exactly one unambiguous contract-valid result. Support standalone JSON, JSON code fences or a documented explicit result delimiter/envelope in chatText, and JSON artifacts. Do not guess from arbitrary braces in narration or accept a memory/input summary as a brief. Multiple distinct valid answers are ambiguous and fail, reaching router fallback.
- Text jobs require explicit result envelope or delimiter. Add three instruction markdown files for the configured remote agents requesting this format; do not change remote agents from the worker.
- Official source: https://docs.creao.ai/pro/api-trigger. See kb/research/sponsors.md for observed output/redirect conventions. No streaming needed. Developer realtime uses a separate NDJSON path and stays out of scope.

## Bounded behavior and testing
- Inject fetch, clock and sleep for deterministic tests; request timeout, total-run deadline, max polls and response-size cap. Abort fetch on timeout. No hidden create-run retry inside transports: router remains at two primary attempts plus at most two Claude fallback attempts.
- Safe failure classes identify provider/job/status category without leaking payloads. Distinguish successful transport from validated job output, and expose actual backend in diagnostic calls.
- Test exact URL/body/auth/version, terminal failures, malformed envelope, poll/time/size bounds, artifact redirects/auth stripping, narrated extraction, duplicate/ambiguous payloads, Claude refusal/truncation, invalid C1 fields and bounded fallback. Existing20router tests remain.
- Manual smoke command accepts one explicit job/backend and synthetic fixture input, loads keys only from caller environment, never prints credentials/raw failures. Disable fallback or assert backend identity so CREAO failure cannot be reported as a CREAO success through Claude. Do not run real calls during implementation. Codex will run bounded authenticated smoke after review.
- Fill Result with public API, commands, implemented extraction formats, bounds, tested cases and known model/output restrictions. No live credentials/ownership/latency claims from mock tests.
