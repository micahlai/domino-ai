## Bounded conversational behavior

A conversation is pinned to one saved source run/inputHash/rule-set version and its selectedWeek/selectedItem context. User and assistant messages form a persisted transcript. Begin by describing a supported cash event, late invoice or supported rule; missing fields produce one specific question at a time, and short replies fill that pending field without requiring a full repeated prompt. Keep known fields across turns. Do not silently change existing supplied values. Ambiguous/conflicting answers, unsupported daily/headcount rules, unsafe money/date/record targets clarify with no financial run. Explicit Start over clears pending proposal; user text is never executed as instructions. A new complete supported request may replace the pending draft only with clear visible reset semantics; prefer Start over when intent changes. No automatic provider or engine calls on messages/reads. Reuse existing questions grammar/intent/parse/resolve read-only; typed pending-intent accumulation in new chat module. Every financial value comes from user words + existing exact parsers or frozen saved records. No invented dates/names/money, no simple concatenation of transcript into a fresh financial prompt. Initial bounded grammar is honest in UI; arbitrary dialogue is not claimed.

Cash event missing amount/date/counterparty; late-invoice missing record/days; cash-min missing amount; runway missing months; bill deadline missing bill/allowed late days. Multiple initial supported intents (max4) can accumulate; clarify missing fields sequentially, retain all already supplied data and rules. Existing resolver supplies valid Proposal with complete replacement constraints retaining old ones; use existing workspace simulate/reviseConstraints only after explicit confirmation. Correct ambiguous invalid values by asking for the same field again, not treating a partial answer as a new unrelated request. Unsupported constraints remain unsupported.

## Frozen public API and receipt
