# Exact-run calculation views, Oct25

User asked to connect scenario creation, map activity, saved simulations and suggestions with relevant calculation graphs and explanations. Real engine work must remain distinct from provider calls; no fake model activity or private model thoughts. Existing passing checks are reused where code is unchanged.

## Backend Field boundary
- New `fieldTrace.get({companyId,runId,scenarioId?,fixKind?})` reads an exact Field analyst run, never latest company state. Validate company/run ownership and scenario/fix membership. A shared browser-safe validated contract lives at apps/web/lib/field-trace-contract.ts, owned by backend worker and consumed by UI.
- Pin model, constraints, company/dataset identity and operating source provenance at startRun. Snapshot ID/version already durable. Every numerical stage and advisor must read the pinned bundle for that run. Existing old runs remain valid; do not manufacture missing old model/constraint evidence from newest rows.
- Existing log.runId is already stamped. Add by_company_and_runId index and exact query. Provider receipt origin may be stamped with optional analyst runId on aiCalls; cache reuse must retain original caller and show cached/reused provenance, not claim another paid call. Apify already has analystRunId.
- Freeze completed/failed Field calculation receipt once on analystRuns via optional validated JSON. Include exact source/version/as-of, pinned model/rules, selected scenario changes/work/fixes, immutable suggestion effects/recommendation, relevant run operations and truthful provider/cache/skipped/error metadata. Source dependency nodes may reference immutable snapshot and frozen connection receipts. Bounded receipts may disclose truncation; never silently substitute latest state.
- An accepted/declined/open suggestion links by companyId+runId+scenarioId+fixKind. Old open rows are upserts, so preserve each run's candidate results in its receipt before later runs replace rows. Trace view is read-only; existing guarded decision semantics remain.
- No new tables. Authorized optional fields/indexes on Field-owned analystRuns/log/aiCalls only, plus their composition tests. No packages/contracts, root schema, Timeline tables/schemas or monetary engine changes. Old incomplete evidence gets a clear legacy limitation; opening a trace never reruns computation/providers.

## Explanation priority
- Latest user clarification: the action is How we got here. Lead with a short result-specific account: data used, assumption/event changed, calculations/checks that actually ran, and why they produced this result/suggestion. Graph/step history supports that account; providers, IDs and raw logs stay secondary. Prefer a clear small recorded-step view over graph complexity.

## UI and Timeline boundary
- Field trace route under /field/analysis uses explicit company/run scope. Hide the current-company provenance strip on saved trace pages and display the frozen run identity/labels instead. Switching selection cannot relabel an old trace. Show only recorded relevant agents/tools plus necessary saved source dependencies.
- Timeline calculation route /c/<company>/timeline/calculation?runId=<exact> reads only public workspace.get and baselines.get (and exact analysis receipt when supplied). Saved workspace creation is synchronous and engine-only, with no persistent running job. Present its saved input/change/forecast/rule-check sequence as recorded calculation, not live AI work. Do not call automatic analysis.start for event descendants: that API currently rejects them.
- New saved scenarios and each saved scenario card offer View calculation/Watch analysis pointing to the returned exact run ID. Each suggestion offers Why this suggestion linking to its frozen Field run and candidate. Do not resolve either link through latest company activity.
- Display task, source books/assumptions, actual tools or model status, saved results, concise rationale and available alternatives/impact. Financial values come from saved engine outputs, not UI or AI arithmetic. IDs, raw JSON and technical function names belong in collapsed Technical details at the bottom.
- Keep the live map stable. Role icon/color is primary, provider is a secondary badge, labels work without color. Multiple active forecasters may share a stable expandable role container. Tool routes/highlights come from actual recorded calls. Group repeated routine checks and translate raw tool names into plain words.
- Pause time stops new clock days; already queued work may finish. Say this plainly. An optional Freeze map control pauses visual updates only and must say that backend work can continue. Do not silently cancel paid/provider jobs or pretend frozen visuals mean completed analysis.
